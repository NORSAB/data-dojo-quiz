## 1. Why Combine CPT and IFT?

To build an enterprise production assistant capable of reasoning over proprietary domain corpora, neither Continued Pre-training nor Instruction Fine-Tuning is sufficient on its own:

- **CPT Alone:** Internalizes deep vocabulary, facts, jargon, and statistical relationships from raw text, but produces a **base model** that cannot hold dialogues, ignores prompt instructions, and simply autocompletes text.
- **IFT Alone:** Teaches conversational turn-taking, style, and formatting, but if the foundational domain knowledge was never in the base model, the model will **hallucinate** plausible-sounding falsehoods when asked technical questions.

### The Sequential Two-Stage Pipeline

```
+---------------------------------------------------------------------------------------------------+
|                              THE SEQUENTIAL CPT + IFT PIPELINE                                   |
+---------------------------------------------------------------------------------------------------+
|                                                                                                   |
|  [ Open Base Model ]                                                                              |
|  (e.g., Llama 3 8B Base)                                                                          |
|         |                                                                                         |
|         v                                                                                         |
|  STAGE 1: Continued Pre-training (CPT)                                                            |
|  - Input: 1B - 50B tokens of raw domain text (.txt)                                               |
|  - Objective: Unsupervised Causal Language Modeling                                               |
|  - Output: Domain-Adapted Base Model (Checkpoint)                                                 |
|         |                                                                                         |
|         v                                                                                         |
|  STAGE 2: Instruction Fine-Tuning (IFT)                                                           |
|  - Input: 10K - 100K domain instruction/chat pairs (.jsonl)                                       |
|  - Objective: Supervised Next-Token Loss (Response tokens only)                                   |
|  - Output: Production Domain Chat Model                                                           |
|         |                                                                                         |
|         v                                                                                         |
|  [ Deployed Domain Expert Copilot ]                                                               |
|  - Retains deep domain factual understanding                                                      |
|  - Fluently executes instructions, respects schemas & system prompts                              |
+---------------------------------------------------------------------------------------------------+
```

## 2. Checkpoint Chaining via MLflow & Unity Catalog

In Databricks, chaining Stage 1 (CPT) into Stage 2 (IFT) is accomplished by referencing the sharded checkpoint symlink generated by the first run.

### Step 1: Execute Continued Pre-training
```python
from databricks.model_training import foundation_model as ft

# Step 1: Launch Continued Pre-training
cpt_run = ft.create(
    model="mosaicml/mpt-7b-8k",
    train_data_path="dbfs:/Volumes/finance_cat/corp_data/cpt_corpus/",
    training_duration="1ep",
    task_type="CONTINUED_PRETRAIN",
    register_to="finance_cat.ai_models.mpt_7b_cpt_base"
)
```

### Step 2: Retrieve the Trained Checkpoint Path
When CPT finishes, the model artifacts are logged to MLflow tracking. The latest distributed checkpoint is linked via a `.symlink` file:
```python
# Checkpoint symlink structure logged in MLflow:
cpt_checkpoint_path = f"dbfs:/databricks/mlflow-tracking/{cpt_run.experiment_id}/{cpt_run.id}/artifacts/checkpoints/latest-sharded-rank0.symlink"
```

### Step 3: Launch Instruction Fine-Tuning using Custom Weights
Pass the output of the CPT run as the input model into the IFT job using the `custom_weights_path` parameter:

```python
# Step 2: Launch Instruction Fine-Tuning using the CPT checkpoint weights
ift_run = ft.create(
    model="mosaicml/mpt-7b-8k",  # Original base architecture
    custom_weights_path=cpt_checkpoint_path,  # Load CPT weights
    train_data_path="dbfs:/Volumes/finance_cat/corp_data/ift_chat_data.jsonl",
    task_type="INSTRUCTION_FINETUNE",
    training_duration="3ep",
    learning_rate=5e-6,  # Conservative LR to preserve CPT knowledge
    register_to="finance_cat.ai_models.mpt_7b_finance_copilot"
)

print(f"CPT+IFT Pipeline Complete. Final Model Registered to: {ift_run.registered_model_name}")
```

## 3. Managing Catastrophic Forgetting

A central risk when fine-tuning or continuing pre-training is **catastrophic forgetting**: the tendency of a neural network to overwrite previously learned general reasoning, mathematical abilities, or general language syntax while optimizing aggressively for the loss on new domain data.

### Diagnostic Signs of Catastrophic Forgetting
- Domain perplexity drops dramatically (good), but general benchmark scores (MMLU, GSM8K, HumanEval) collapse by >15%.
- The model forgets basic coding syntax or common world knowledge.
- The model repeats domain buzzwords uncontrollably regardless of context.

### Engineering Mitigations

1. **Replay Buffer (Data Mixing):** Mix **5% to 15% of high-quality general open-domain text** (e.g., SlimPajama, Wikipedia, Python code) into the Continued Pre-training corpus. This forces the attention heads and MLP layers to preserve representations for general grammar and logic while learning new domain representations.
2. **Conservative Learning Rate Decay:** In Stage 2 (IFT), use a learning rate 5× to 10× smaller than the CPT learning rate (e.g., $5 \times 10^{-6}$ vs. $3 \times 10^{-5}$).
3. **Warmup & Cooldown Schedules:** Employ a cosine learning rate decay with a linear warmup phase (typically 1–2% of total steps) to avoid gradient shocks at the beginning of each training stage.

## 4. Risks and Challenges Matrix

| Risk / Challenge | Underlying Mechanism | Recommended Solution |
| :--- | :--- | :--- |
| **Overfitting / Memorization** | Training for too many epochs on a small domain dataset. | Keep CPT to 1–2 epochs maximum. Monitor validation loss; stop when eval loss plateaus. |
| **Loss Spikes** | Unstable gradients caused by low-quality or corrupt text tokens. | Apply gradient clipping (e.g., `clip_grad_norm=1.0`), remove malformed Unicode characters during data prep. |
| **Format Collapse** | IFT training dataset has monotonous responses, causing the model to lose output diversity. | Ensure IFT data contains diverse lengths, formats, multi-turn dialogues, and refusal examples. |
| **Context Window Mismatch** | Pre-training at 2K sequence length, then attempting 8K inference. | Pre-train and fine-tune using consistent sequence lengths, or apply RoPE frequency scaling if expanding context. |
